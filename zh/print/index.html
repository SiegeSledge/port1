01

《流量裁缝》Tailor of Traffic

一款关于时尚电商注意力经济的讽刺经营游戏：衣服越离谱越好卖，直到买家秀和退货戳穿假象。

角色
设计与开发（借助 AI 编程工具实现）
时间
2026 年 11 月
机构
个人项目

核心成果

  • 24 种部件、5 种面料、3 个拍摄场景；一局三季，约 20–30 分钟
  • 第 1 季示例：售出 38 件，退货 13 件，净利 ¥221
  • 浏览器版 + Unity（C#、URP）移植版，中英双语
  • 游戏设计
  • 系统设计
  • 经济设计
  • 信息设计
  • Three.js
  • Unity
  • 中英双语

概述

《流量裁缝》（Tailor of Traffic）是一款中英双语的浏览器游戏：玩家扮演一名学会“为注意力经济做衣服”的服装设计师——拼装服装、摆拍并修图、定价和定产量，再看顾客实际收到的东西。订单暴增也可能在退货到来之后亏钱。

灵感来自对网络服装零售的一个观察：一件怪异的衣服能吸引注意，商品摄影能让它显得诱人，而顾客的买家秀几秒钟就能戳穿这层幻觉。完整游戏之后又移植到了 Unity。

设定

设计师屡屡被市场拒绝。两次脚本化的失败建立起处境，随后设计师觉醒了一个能显示每个设计元素受欢迎程度的“系统”，从此靠缝合流量词条做出越来越离谱的爆款。基调是荒谬、欢乐、讽刺，核心画面是：设计师一边心里想着“这衣服真蠢”，一边为了恰饭给衬衫加上第六个袖子。

概念阶段的参考：

  • 《Game Dev Tycoon》：创意决策与经营结果挂钩。
  • 《Reigns》：简单决策，后果之后才出现。
  • 《Papers, Please》：用玩家重复的工作表达主题。
  • 《Good Pizza, Great Pizza》：让熟悉的工作因顾客而变得好笑。

这些想法最终落在同一件衣服的“卖家秀 vs 买家秀”并排揭示上。

核心循环：三个环节 × 三个季度

1. 设计

每季从裁剪台开始。玩家选择两种底版之一（衬衫 80 元或连衣裙 100 元）、从 5 种面料中选择，并在领、臂、胸、下摆和额外部位最多挂 24 个部件。部件可以复制、缩放、在槽位之间移动。实习生在角落的预览里试穿并吐槽（“别告诉别人我在这上班”）。市场热度和成本可见；衣服背后的评分在编辑时不可见。

2. 拍摄

玩家选择模特（实习生 200 元一口价，或超模 15 元/秒按时计费）、三个场景之一（白棚、工地或海边）和最多两件道具。拖动肢体手柄摆姿势，再用三个滑块修图：胶片氛围、面料质感、黄金比例。

拉动“黄金比例”会在屏幕空间里拉伸模特比例，同时扭曲背景。海边场景里重度修图会让海平线和海岸线一起弯掉。海平线、门框和栏杆就成了玩家自己能看见的证据。

3. 店铺与发售

拍完之后，玩家设定零售价和产量，并决定怎么处理往季的库存。发售结算会揭示需求、退货、差评和账单，并把精修封面和买家秀放在一起。

某次第 1 季的结果：卖出 38 件，收入 2,475 元，但退回 13 件。扣除生产 1,950 元、退货运费 104 元、模特费 200 元和打样费 195 元后，净利 221 元。

季与季之间

  • 每季都要付房租，趋势也每季变化，所以第 1 季的爆款不会延续。
  • 第一件被骂的衣服挂在工作室里，它的状态反映设计师三个季度里的选择，并在结局回归。
  • 设计文档还设想了：市场热度会饱和（大家都做短袖，短袖就不值钱了）、系统数据有滞后、竞争对手会抄爆款——让玩家不能只对着看得见的数字求最优解。

设计原则：信息可见性

设计文档给每个指标、阈值和事件都标了可见性档位，因为设计者知道的，不等于玩家需要看到的。

档位 含义 例子
可见 界面直接显示数字 风格热度、成本、预算
暗示 不给数字，用画面或角色反应表现 实习生的表情、弯掉的门框、墙上蒙灰的衣服
事后揭示 发售或结算时才知道 销量、退货、差评、触发了哪个隐藏词条
隐藏 永远不给数字，靠玩家摸索 隐藏词条的条件、离谱度甜区

这条规则带来的后果：

  • 系统只显示流量，不显示后果，这本身就是讽刺点。
  • 内部指标名不会出现在界面上；玩家看到的是听起来高级的行业黑话。
  • 设计、摆姿势、修图过程中没有实时分数，反馈只在动作之后（发售或结算）出现。
  • 不解释笑点：卖家秀和买家秀并排放，差距一眼就懂。

试玩反馈与随之而来的改动

玩家反馈 回应
觉醒时系统说过什么记不住，离开看板就找不到 在趋势看板、设计、拍摄和店铺都加一个可随时呼出的“系统”入口
数值和箭头很难懂 在系统面板里用大白话解释公开的热度与走向指标
开局变量太多 随季度逐步开放指标（提议中）
希望用赚到的钱买更多设计选项 可购买的解锁项（提议中），并写清解锁价格和每季打样成本
拍摄时摆好的道具有时自己跑掉 已定位到猫的定时移动；其他情况待复现

由此做出的系统面板解释 8 个公开的热度与趋势指标，并回看本季与往期的热搜。面板内容读取已有的季度数据，因此不新增存档字段。打开面板会保留当前画面，并暂停模特的计费计时；关闭后恢复焦点。

技术

浏览器版。 TypeScript、Three.js 和 Vite。场景以 480 × 270 渲染并带深度纹理；全屏后处理在最近邻放大之前加入深度描边和 64 色 OKLab 调色板匹配。模型由盒体拼成，服装部件有挂载槽位，摆姿势用双骨骼 IK，拾取和遮挡用简化的代理盒体。比例修图是屏幕空间的扭曲，背景会随模特一起变形；同一套变换在 TypeScript 里也实现了一份用于交互。模拟层（服装属性、需求、退货、季间转换）写成纯函数并可注入随机源，与渲染器分离。面向玩家的文本放在中英文 JSON 文件里。

Unity 移植版。 使用 Unity 6000.6.9f1、URP 17.6 和 Input System，沿用 C# 模拟层、体素导出和像素着色器。完整流程（语言选择、两次开场失败、觉醒、三个季度、结尾和重开）在 macOS 播放器中以中英文、1280 × 720、844 × 390 和 568 × 320 三种窗口尺寸跑通。

开发过程

工作按里程碑推进：正交像素渲染器与工作室；按规格设定参考打法的确定性模拟；一个可玩的季度；更多场景、道具、遮挡和隐藏事件；最后是开场、结尾和三季结构。双语版本单独开发后合入主工程。交接记录（AGENTS.md 与 PROGRESS.md）让工作能在 Claude Code 与 Codex 之间接力。

局限与下一步

  • 实现借助 AI 编程工具完成；设计、规格、取舍和试玩判断是我做的。
  • 目前只有内部试玩。首次游玩的玩家能否讲清楚市场热度并据此选择设计，仍是开放问题。
  • 已知缺陷：如果季度看板在照片解码完成前存档，之前的照片可能变成透明。
  • Unity 移植版还没有 Android 构建，568 × 320 下部分按钮偏小。
  • 计划中的下一轮迭代：逐步开放指标、可购买的设计选项。

《课桌下的米其林》Michelin Under the Desk

一款上课偷吃的单人潜行 roguelite：按住空格低头进食，松开抬头看老师，按 S 把食物藏进桌肚。

核心成果

  • 镜头约 0.28 秒沿同一路径低头 / 抬头

概述

《课桌下的米其林》（Michelin Under the Desk）是一款单人浏览器 roguelite：上课偷吃零食，看你能在老师回头之前做到什么程度。

灵感来自一个很小的决定：粉笔摩擦黑板的声音停了，你是把零食收起来，还是再多吃一口？之后这个想法被越推越难以解释：如果要藏的是一锅还在冒烟的火锅呢？

玩法

  • 按住空格低头看桌洞并进食，松开抬头观察老师。
  • 低头时按 S 把食物收进桌肚。松开空格只是停嘴，食物仍可留在桌面，直到被收起。
  • 已开火的火锅藏好之后仍然冒烟。
  • 句号键开关调试面板（默认隐藏）。

结构

游戏有普通教室、图书馆和考场三类场景，每类三节课、每节 90 秒，之后是主任办公室的烹饪终局。共有 9 种食物、24 张升级卡、局外成长和 3 种结局。

食物的“代价”各不相同：辣条袋好藏，薯片太响，螺蛳粉的气味会飘向邻座，开火的火锅藏好后仍然冒烟。达到一节课的配额后，课间可以从三张升级卡里选一张，让一局更偏向安静地吃、更快地咽下，或把怀疑引向别处。

局间有一个一本正经的系统，把偷吃当成可以精进的学科；课堂里赚到的积分会解锁卧室里的剧情片段。到了主任办公室，原来会暴露你的香气，反而成了主任走到桌前的原因。

设计决策

把“看老师”变成玩家的决策

首轮内部试玩时，我发现自己总在盯着状态灯——它告诉我老师在做什么，侧栏还显示视线、声音、气味和座位位置。我把这两样都藏进了调试面板，换成声音线索：粉笔停笔的碰声、两层脚步（鞋跟落地与摩擦）、图书馆和考场的翻纸声。现在玩家要靠听到的声音决定什么时候停嘴。

重做低头镜头

第一版低角度原型是从教室硬切到一个木质桌洞，零食包装袋像悬浮在画面中央：桌洞占满画面，没有手和袖口。后来重做为同一座位的第一人称视角。镜头约 0.28 秒沿同一路径下沉、再沿同一路径返回，同样的袖口、手指和膝盖把动作和玩家连在一起。包装袋先滑出桌洞再转正，按 S 时沿原路收回；大小保持一致，碗和锅保持水平。这一轮还修了两个几何 bug：食物尺寸被二次缩放，以及扁平的包装袋会穿过桌洞后壁。

音频

低头时压低音乐，免得盖住咀嚼和脚步声；图书馆的翻纸声和玩家的包装声分开；粉笔停笔的那一下碰声更脆。

一个输入边界

按住空格时短按 S，曾经会被下一帧的进食输入取消。现在 S 开始收纳后，继续按着空格仍保持低头，直到收纳完成；要再次拿出食物必须重新按下空格。

市场调研

课堂潜行已经有参考：《Worst Class Ever》（开发者自述首日销量超过 10 万份）、itch.io 上的《Classroom Snacks》和《Don’t Get Caught》。我关注的问题是：手里的食物应该怎样改变你的下一步。

技术

TypeScript、Vite、Three.js（WebGL2）和 Web Audio。课堂模拟以固定 60 Hz 步长运行，便于把时序和渲染分开测试。所有可见模型都是程序化体素，并预留了 Tripo GLB 模型的插槽。

演示

33 秒的实机录像带双声道游戏原声。它使用固定种子，安排一次回头和一次巡逻，让两个线索出现在同一条连续镜头里。画面来自游戏渲染器，加了操作字幕，未剪辑。

局限与下一步

  • 浏览器版是我写好构建需求、借助 AI 编程工具完成的；上面的设计决策是我做的。
  • 目前还没有外部玩家观察，也没有真人试听。悬而未决的问题是：新玩家能不能听到粉笔停下、把零食收起来，并在被抓时讲清楚是什么暴露了自己。
  • 已知问题：手机竖屏时“书”按钮会压住食物卡。

项目一：AI 赛后复盘助手

问题

新玩家能完成基础操作，但很难理解一局游戏背后的决策。原始回放和文字总结并不能告诉他们错在哪里、该练什么。

设计

  • 把关键战局事件、游戏机制知识和个性化建议组织成闭环：定位问题、解释原因、训练建议。
  • 交付了核心流程、交互原型、可运行 Demo 和 Multi-Agent 架构设计。
  • Demo 中，AI 通过 Function Calling 调用预设的事件查看器来读取结构化对局事件，使分析能落到具体行为上。
  • 天赋推荐与解释场景使用 RAG 检索 Wiki、游戏术语以及技能 Counter / Combo 信息，使建议同时结合真实对局证据与领域知识。

自然语言与 GUI 的分工

我探索了在 AI 教练场景里语言和图形界面该如何分工：自然语言负责解释、追问和个性化建议；时间节点、关键事件和结构化信息帮助玩家定位问题，避免把复杂战局压缩成无法验证的文字回答。

项目二：摸金模式背包快捷替换

问题

高压战斗中，玩家需要快速决策，却承担不起误操作。

设计

  • 物品推荐、预览确认、一键替换和异常保护机制。
  • 为工程梳理推荐规则、系统状态和数据需求。
  • 方案推进到测试服验证。

工作方式

  • 与策划、程序、美术开展原型评审和版本验证，并跟进体验问题直至闭环。
  • 输出交互流程、推荐逻辑和数据接口需求。
  • 结合 AI Agent、Figma 和代码生成工具做需求分析、原型开发与验证，提升迭代速度和跨职能协作效率。
  • 独立完成 UI 交互相关的专利交底材料。

概述

TransitEase 是一款面向纽约地铁中残障乘客、轮椅使用者和携带大件行李人群的应用，把实时路况、无障碍导航与社区反馈整合进同一个决策流程。这是我在 Ji Woo 教授指导下完成的独立项目，同一主题也是我上海纽约大学毕业论文的研究对象。

问题

选择纽约作为代表性的试验场有两个原因：MTA 的无障碍问题被广泛讨论，而且纽约交通有足够多的数据和既有研究。尽管有电梯等无障碍设施，残障乘客仍然从两端遇到困难：

  • 服务方（如 MTA）缺乏足够的无障碍基础设施，也无法收集无障碍设施是否可用的实时数据。
  • 用户方：地图软件依赖过时的无障碍设施与目的地信息，导致行程规划和路线建议不准确。

经历一次失败的迭代之后，最终思路依靠众包与通用设计。

研究

  • 案头研究与用户画像。
  • 在主要地铁站访谈 30+ 位残障人士，识别路线规划、设施状态与临时求助中的断点。

设计

  • 负责信息架构、关键用户流程与高保真原型：用 Axure RP 画用户流程，Figma 做线框和 UI。
  • 搭建可运行的原型：VS Code 写前端，MySQL 做后端数据库，Google Maps API 实现 GPS 与地图功能，把导航、设施信息与社区反馈整合在一起。
  • 增加内嵌地图的用户社区，并根据真实使用反馈调整信息优先级和任务流程。
  • 引入代币奖励机制以提升可持续使用，并探索与慈善组织合作的收入来源。

成果

  • 累计沉淀 200+ 深度使用用户，验证了无障碍导航与社区信息共享的真实需求。
  • 毕业论文：Community-based solution to disabled transportation: A community-based AI-empowered solution of routine planning for disabled people（上海纽约大学，2025 届）。关键词：crowd-sourcing、accessible design、universal design、route planning、real-time accessible data。

Immersive Trap（沉浸式陷阱）

一件展览式作品，探讨 AI 驱动的个性化如何构建信息茧房与回音室。

概述

Immersive Trap 是一组空间展览概念设计：把看不见的算法推荐与回音室效应转译为实体空间装置，探讨个性化系统如何在让人感到“顺手”的同时，悄然收窄人的视野。

研究与概念拆解

问题的成因

  • 心理基础：人对熟悉观点有天然偏好，确认偏误会促使人不断寻找印证既有立场的信息。
  • 算法放大：2000 年代初普及的推荐系统以停留与互动为优化目标，无意中加速了信息茧房的形成。
  • 媒体碎片化与注意力变现： 选择性接触早于互联网，而定向广告让平台更倾向于奖励高互动内容，进一步压缩多元信息触达。

AI 的角色

每一次点击、停留和互动都在喂养协同过滤与基于内容的推荐模型，使反馈闭环越收越紧，逐步推高观点极化。

从研究到空间呈现

  • 结合 YouTube、TikTok 等视频平台的推荐机制，拆解回音室从反馈闭环到长期固化的演变阶段。
  • 将研究结论转化为空间隐喻、实体模型搭建与观展动线设计。

Pause NYC

一个文化旅游体验：通过展示建筑与景点的背景信息，并把路线变成"解锁"游戏，让纽约的节奏慢下来。

概述

Pause NYC 想解决纽约旅游中「打卡很快、体验很浅」的问题：通过呈现建筑与地标背后的历史信息，并把城市步行路线做成「路径点解锁」玩法，让游客和本地居民都能按自己的节奏重新发现城市，并记录、分享行走足迹。

研究发现

  • 纽约本地地标基数：据纽约市地标保护委员会，纽约五大行政区有 300 多个风格各异的社区，以及 37,000 多座受保护地标建筑与场所。
  • 游客结构：在疫情前典型年份（2018–2019），约 80% 的纽约游客以休闲为主、20% 为商务出行；NYC & Company 预测总游客量最早在 2024 或 2025 年接近或超过疫情前峰值（6,660 万人次）。
  • 热门景点集中： 帝国大厦、克莱斯勒大厦、世贸中心一号楼、洛克菲勒中心、自由女神像和中央公园吸收了绝大部分游客注意力。
  • 本地人同样缺少探索动机：在对 1,200 多名纽约居民的调查中，40% 的人近两年没去过任何五大热门景点。
  • 本地高频空间参考：据报道布莱恩特公园约有 60% 为本地人使用，免费活动与开放绿地形成了更稳定的日常吸引力。

设计重点

  • 分别访谈外地游客与纽约本地居民，拆解两类人群在路线规划与文化信息获取上的差异需求。
  • 对比 Google Maps 等现有导航与攻略工具，明确「地标背景 + 轻游戏化解锁」的切入点。
  • 输出价值地图、核心用户流程、带 3D 建筑视图的网页界面设计与交互演示原型。
